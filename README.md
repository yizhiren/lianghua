# 量策 · 沪深港股策略跟踪

量策是一个本地运行的股票策略与自动交易工具，用于从沪深 A 股与港股中筛选候选股票、维护策略持仓，并把量化信号转换为可审计的模拟订单。当前内置模拟券商；真实券商需要实现通用适配器后才能启用。

## 已实现能力

- 两列策略工作台，可新增、暂停、编辑和归档策略。
- 自动待定股票按最新一轮扫描维护快照，不跨交易日累加；手动加入和从持仓放回的股票保留。
- 待定股票与模拟持仓的手动添加、删除、互转以及盈亏展示。
- 版本化 JSON DSL，支持 MACD、SMA、EMA、RSI、KDJ、BOLL、ATR、ADX、波动率、价格突破和成交量规则。
- 支持日K与最近完整周K的跨周期组合、均线偏离率、K线实体、缩量、连续确认和指标相对变化。
- 支持建仓、加仓、减仓、清仓和硬止损信号转换为幂等订单意图；买入人工批准，卖出和止损自动执行。
- 内置 CNY/HKD 独立资金账户、策略资金配额、单股/单策略敞口限制、当日亏损冻结买入、T+1、账实对账和紧急停止。
- 订单每15秒处理；买单默认次交易日开盘执行、09:20前批准、10:00撤单，普通卖单采用价格保护，硬止损持续重试至成交。
- 持仓可记录每次实际补仓；自动更新数量和加权成本，并冻结首次补仓时的20日低点与低点后反弹快照供策略使用。
- 新建和编辑策略采用多轮对话：原始自然语言先整理为可确定解析的受控自然语言，再由本地编译器生成 DSL。
- 每 15 分钟调度、手动执行、当前信号高亮、信号变化历史和失败后陈旧标记。
- SQLite 本地持久化，以及沪深港 AKShare 免费公开真实行情适配器。
- 四赛道规则策略训练平台：左侧/右侧分别在 A 股/港股上搜索、滚动验证、压力测试，人工批准后才进入模拟盘。

## 本地启动

需要 Python 3.9+ 和 Node.js 22.13+。

先确认 Node.js 版本：

```bash
node -v
```

如果低于 22.13，macOS 可使用 Homebrew 安装 Node.js 22：

```bash
brew install node@22
```

`start-local.sh` 会自动查找 Homebrew 安装的 Node.js 22，无需每次手动修改 `PATH`。

首次初始化并启动：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm ci --no-audit --no-fund
test -f .env || cp .env.example .env
./scripts/start-local.sh
```

浏览器访问 `http://localhost:3001`。FastAPI 文档位于 `http://127.0.0.1:8010/docs`。

## 自动交易配置

默认配置只会在本地模拟账户成交，不会向任何真实券商发送订单：

```dotenv
TRADING_MODE=paper
BROKER_ADAPTER=paper
LIVE_TRADING_ENABLED=false
PAPER_CNY_CASH=1000000
PAPER_HKD_CASH=1000000
MAX_SECURITY_EXPOSURE_PCT=10
MAX_STRATEGY_EXPOSURE_PCT=30
DAILY_LOSS_PAUSE_PCT=2
```

策略只有在“自动交易控制台”启用对应 CNY 或 HKD 资金配额后才会生成订单。建仓/加仓信号进入待批准队列；减仓、清仓和硬止损会自动进入执行队列。模拟成交会同步更新券商账本、策略持仓、成交记录和审计日志。

`backend/app/brokers/base.py` 定义了真实券商适配器必须实现的健康检查、行情、余额、持仓、限价下单、成交轮询和撤单接口。当前发布版仅注册 `paper`；将 `BROKER_ADAPTER` 改为未安装的名称会拒绝启动，将 `TRADING_MODE=live` 与 `paper` 组合也会拒绝授权或下单，避免误把模拟成交当成实盘。

修改交易配置后需要重启后端服务。首次升级启动会自动创建交易表，并从现有策略持仓初始化模拟券商持仓；CNY 与 HKD 不自动换汇。

## 策略回测

工作台“策略回测”区域可以选择策略和日期范围直接运行历史逐日重放。任务提交后在后台运行，页面每次刷新或收到心跳时更新状态，不会长时间占用HTTP请求。回测严格使用当时已经完成的日K：T日收盘计算信号，订单最早在该股票下一交易日开盘成交，不会用T+1数据判断T日条件。

默认假设包括：CNY/HKD各100万元、缺省目标仓位10%、单股上限10%、开盘滑点0.1%、佣金0.03%且最低5元、卖出税费0.05%、建仓日低点下方3%止损、最长持有60个交易日、期末强制平仓。所有策略自身的目标仓位、加仓、减仓、清仓和止损规则仍会参与重放；策略没有填写目标仓位时才使用缺省仓位。

回测结果会保存以下数据：

- CNY、HKD分币种权益和归一化净值曲线；
- 总收益、年化收益、最大回撤、夏普、平仓胜率和总费用；
- 每个买入信号之后5、10、20、60个交易日的平均收益与胜率；
- 所有信号、模拟成交、成交原因和已实现损益。

API为 `POST /api/backtests`、`GET /api/backtests` 和 `GET /api/backtests/{id}`。回测使用当前数据库证券池；若数据源没有历史退市股票和历史ST状态，结果会存在幸存者偏差，页面会持续显示该警告。费用和滑点是研究假设，不代表真实券商结算。

## 策略训练中心

工作台“策略训练中心”维护四条完全隔离的赛道：左侧 A 股、右侧 A 股、左侧港股和右侧港股。左侧模板寻找120日低位和 RSI 超卖，但必须同时出现 MACD 柱、RSI 拐头，并用 MA200 价格下限、MA120 斜率和 ADX 上限排除陡峭下跌中的“接飞刀”，退出使用 ATR 初始止损和均值回归目标；这里的 MACD 动能统一指柱值而不是 DIF。右侧模板搜索放量突破、长期均线斜率、突破日涨幅上限、ADX/ATR 趋势质量、可选周线共振和 ATR 移动止损，不再混入难以解释的回踩分支。A 股可在55/120日突破之间选择，使用当日成交量相对20日均量，额外要求 MA200 相比60个交易日前上升，并用20/40日低点通道、ATR或最长持有期退出；港股固定使用55日突破，并以5日均量相对20日均量减轻单日成交噪声。A 股同日信号按20日动量、港股按60日动量排序。参数搜索只在这些有经济含义的模块内组合，不允许任意堆叠指标。

训练是持续迭代而不是单次定参。快速训练每赛道比较12组候选，完整训练比较200组；每组参数都要经过3段时间滚动验证和最后20%隐藏留出集。开发期评分使用下四分位收益/夏普，并惩罚最差折回撤、折间波动、任何亏损折，以及合计不足100笔或任一折不足15笔的稀疏样本，不能再由两个好区间或少数幸运交易掩盖一个坏区间；最终研究候选也必须先满足这两项开发期样本门槛，隐藏留出集只用于验收，不能反向挑参数。每轮会先在新快照上重测兼容的现任冠军，再用新的随机种子生成挑战者；最优挑战者还要对每个连续/整数参数分别做上下邻域扰动，避免把多个阈值同时移动造成的伪不稳定。已通过门槛的正式冠军要求至少2%的相对评分改善，且仍需人工批准。

每次训练都会流式冻结一份不可变 Parquet 日K快照，并由 DuckDB 复核行数、股票数和重复键。历史数据会从上次已复权末日增量下载，并用重叠日校准旧数据的复权尺度；最新复权覆盖不足95%时禁止正式训练。港股快照会排除临时并股柜台、名称带“新/旧”的临时计数器、ETF、债券、优先股、存托凭证、越过退市日的K线及无效价格；市场代理对每日横截面收益做1%/99%缩尾，避免单个异常代码污染基准。训练按时间顺序划分三个开发折和最后20%的隐藏留出集，按模拟盘30%策略总敞口、单股最多10%逐日盯市；同日信号超过仓位容量时按当时可见的反转/趋势强度排序，不再按股票代码先后选股。市场代理按每个候选的实际平均持仓比例缩放，避免用间歇持仓策略对比每天固定30%持仓的基准。Deflated Sharpe在整轮结束后根据开发期全部候选的真实Sharpe方差和月收益相关性计算；旧版把亏损折比例称为PBO的近似已停用，因为它既不是真正的CSCV/PBO，又与“三折全部盈利”重复。系统保存每个候选的参数、折叠指标、交易次数、胜率、盈亏比、MFE/MAE、成本压力、等仓位市场代理、Deflated Sharpe概率和参数邻域稳定性。晋级必须同时满足：

- 至少10年历史、股票池与最新复权日K覆盖率均不低于95%，且具备历史 ST/退市/成分的时点状态；
- 留出集最大回撤不超过15%，绝对收益为正，夏普不低于0.8，且年化收益高于同平均仓位的等权市场代理；
- 三个开发折全部盈利，开发期合计至少100笔且每折至少15笔，成本压力、开发期Deflated Sharpe和参数邻域稳定性全部过关。

训练采用“数据建设 → 正式训练 → 人工批准”三阶段流程。数据门槛未满足时，仅允许12组快速检查来验证计算链路；手动或定时完整训练会被明确阻断，历史快速检查结果只作为调试信息，不再被标成有效的策略晋级结论。满足所有门槛后，点击“批准进入模拟盘”才会把冠军参数编译为版本化 DSL；系统不会自动发布或自动开启真实交易。

日常操作：

1. “快速检查”使用12个候选验证数据和训练链路；只有所选市场数据就绪后，“完整训练”才可用，默认每赛道200个候选。
2. 工作日17:30自动记录数据健康状态；市场首次达标时自动发起对应赛道的完整训练，此后周六02:00仅为数据已就绪的赛道启动下一轮挑战者迭代。
3. 训练在后端线程运行，页面显示数据快照、技术特征构建和参数搜索阶段，并支持安全取消；服务重启后会自动复用原有不可变快照、恢复已经成功的候选，并从中断处继续剩余预算。同一批次的左右策略会共用对应市场的已校验快照和内存技术特征；后续批次若最新交易日与回填水位均未变化，也会安全复用最近快照，避免重复导出数百万根日K。

API为 `GET /api/data-quality`、`POST /api/training/campaigns`、`GET /api/training/campaigns`、`GET /api/training/campaigns/{id}`、`POST /api/training/campaigns/{id}/cancel`、`POST /api/training/champions/{track}/approve` 和 `POST /api/training/daily-check`。

## 停止服务

在项目目录执行停止脚本：

```bash
./scripts/stop-local.sh
```

脚本只会停止工作目录属于当前项目的 3001/8010 端口进程。若只想查看它将停止哪些进程，可先运行 `./scripts/stop-local.sh --dry-run`。

如果使用 `./scripts/start-local.sh` 在前台启动，也可以回到运行该命令的终端并按 `Ctrl+C`。两种方式都会同时停止前端和后端；仅关闭浏览器页面不会停止服务。

如果前端和后端是在不同终端中分别启动的，需要在两个终端中各按一次 `Ctrl+C`。

若终端已经关闭但端口仍被占用，先查询对应进程：

```bash
lsof -nP -iTCP:3001 -sTCP:LISTEN
lsof -nP -iTCP:8010 -sTCP:LISTEN
```

确认输出中的 PID 属于本项目后再停止：

```bash
kill -TERM <前端PID>
kill -TERM <后端PID>
```

再次执行上面的 `lsof` 命令且没有输出，即表示服务已完全停止。

默认组合使用 AKShare 与 BaoStock 公开真实行情。在 `.env` 中保持以下配置：

```dotenv
MARKET_DATA_MODE=akshare
MARKET_HISTORY_YEARS=15
MARKET_BACKFILL_RETRIES=3
BACKFILL_BATCH_SIZE=100
```

启动后调用 `POST /api/market/sync` 可立即同步，正常运行时也会按调度更新。免费港股行情通常约有 15 分钟延迟；全市场15年历史数据会按批次逐步回填。真实行情模式不会在启动时写入演示证券、演示K线、演示策略或模拟持仓。

在 `akshare` 模式下，A股使用 BaoStock 的15年前复权日线，同时保存每日 `isST` 与交易状态；港股优先使用 AKShare 东财长期接口，失败时切换新浪接口。沪、深、港股票每15分钟轮流处理一批，失败任务按指数退避自动重试。每周日01:00同步A股当前及历史退市证券主数据。`GET /api/market/backfill-status` 可查看每个市场的长期回填进度，也可以调用 `POST /api/market/backfill-next?limit=30` 手动增加一批任务。

## 可选 AI 配置

自然语言策略可调用任意兼容 OpenAI Chat Completions 协议的服务：

```dotenv
AI_BASE_URL=https://example.com
AI_MODEL=your-model
AI_API_KEY=your-key
AI_TIMEOUT_SECONDS=60
AI_RETRY_ATTEMPTS=3
AI_RETRY_BACKOFF_SECONDS=1
```

每轮对话默认最多请求 3 次，临时网络错误、超时、HTTP 429 和服务端 5xx 会按退避间隔自动重试。全部失败后，本轮会停在失败状态，页面显示“重试本轮AI请求”；系统不会改用本地规则校验、不会生成本地助手回复，也不会创建 DSL。HTTP 400/401/403 等配置或请求错误不会进行无意义的重复请求。

密钥只从环境变量读取，不写入数据库或日志。模型输出必须通过 DSL 白名单和参数校验，不能执行任意代码。修改 `.env` 后需要重启服务才能生效。

启动服务后，在另一个终端持续查看最近 100 行后端日志：

```bash
./scripts/logs.sh
```

只看警告、错误和 AI 请求失败：

```bash
./scripts/logs.sh --errors
```

也可以指定初始显示行数：

```bash
./scripts/logs.sh --lines 300
```

日志默认写入 `.runtime/backend.log`，采用逐行 JSON，包含请求 ID、HTTP 路径、状态码、耗时，以及 AI 对话 ID、重试次数、模型和错误类型。日志会在 5 MB 时轮转，最多保留 5 个历史文件；不会记录 API Key、完整对话正文或完整 AI 响应。可通过 `BACKEND_LOG_PATH` 修改路径。

## 策略对话与编译

点击“新建策略”或策略卡片的编辑按钮后，左侧为策略对话，右侧为规则化自然语言和 DSL 预览。每轮请求都会把原始用户消息、历次 AI 回复和最新用户消息作为标准多轮消息完整提交给 AI；是否仍有歧义、是否接受了上一轮建议，以及下一步应该追问还是生成规则化文本，都由 AI 根据对话历史判断，后端不使用关键词规则替 AI 判断。

确认后的规则化文本使用固定结构和条件函数，例如：

```text
规则：weekly-watch-pool
对象：全市场
默认周期：跨周期
日K口径：包含盘中临时日K
条件：全部满足(连续上升(完整周K.MACD.DIFF,2),小于(日K.RSI[period=14],60))
动作：加入待定
标签：完整周K趋势向上且日K不过热
```

规则化文本到 DSL 的步骤不调用 AI，而是由确定性解析器完成；但只有 AI 成功返回并消除歧义后才会进入这个编译步骤。对话、原始描述、规则化文本、编译结果和激活版本会一起保存在本地数据库中。

### 滚动指标与跨序列定位

指标参数支持以下可组合变换：

- `window_op=min/max/mean;window=N`：计算含当前K线的N期滚动最小值、最大值或平均值。
- `select_by=price.close;select_op=min/max;select_window=N;select_tie=first/last`：在另一序列的N期极值日读取当前指标；重复极值可明确取最早或最晚日期。
- `scale=M`：把指标结果乘以固定倍数。
- `lag=N`：读取前N根同周期K线上的指标结果；滚动计算完成后再应用偏移，因此可精确表达T-1时点的滚动窗口。

例如，最近20日最低收盘价乘以1.02可写为 `日K.收盘价[scale=1.02;window=20;window_op=min]`；最近20日内最早最低收盘价对应的DIF可写为 `日K.MACD.DIFF[fast=12;select_by=price.close;select_op=min;select_tie=first;select_window=20;signal=9;slow=26]`。成交量5日均值写为 `日K.成交量[window=5;window_op=mean]`。

规则使用 `日K口径：仅使用已完成日K` 时会忽略盘中临时K线。A股在15:01、港股在16:01同步收盘快照后，系统分别将对应市场当日K线标记为完成。持仓建仓时会记录建仓交易日，并以该日K线最低价提供 `持仓.建仓日最低价`，可用于收盘止损规则。

股票池还可使用 `日K.沪深A股`、`日K.ST股票`、`日K.上市交易日数` 和 `日K.一字跌停`。上市交易日数按系统中截至判断日的已完成日K根数计算，历史数据不足时采取保守策略，不会把标的误判为已满120日。一字跌停要求开、高、低、收四价均等于按前收盘价计算并四舍五入到0.01元的跌停价，且当日成交量大于0；主板使用10%，创业板和科创板使用20%。上市前五日不设涨跌幅的股票会先被“上市交易日数≥120”条件排除。

### 补仓状态策略

持仓列表中的“记录补仓”会保存成交数量、成交价和时间。补仓状态按“策略 + 股票”独立保存，同一只股票在不同策略中互不影响；从持仓删除或放回待定时，会清除该策略下该股票的补仓次数、补仓成交价和首次补仓快照，之后重新建仓会从0次开始。首次补仓时，系统只读取补仓时点之前最近20个已完成日K；若最低价重复出现，以最后一次最低点为准，且最低点当日不参与“之后的最高价”计算。固定反弹公式为：

```text
最低点之后的最高价 >= 20日最低价 * 1.05
```

在策略对话中可以直接使用这些说法：补仓次数、前一次补仓价格、距前一次补仓自然日数、距上次买入或补仓自然日数、首次补仓时20日最低价、首次补仓时最低点后最高价、首次补仓时反弹幅度百分比、首次补仓时反弹已确认。“距前一次补仓自然日数”在没有补仓时为空；“距上次买入或补仓自然日数”则会在没有补仓时从建仓时间开始计算，补仓后改从最近补仓时间计算。例如：

```text
持仓股票首次补仓时已经确认最低点后的5%反弹，并且当前收盘价低于前次补仓价格时，提示加仓至60%。
```

对应的规则化条件形如：

```text
条件：全部满足(等于(持仓.首次补仓时反弹已确认,1),小于(日K.收盘价,持仓.前一次补仓价格))
```

这些是持仓事件状态，只有在持仓区手动记录过补仓后才有值。首次补仓所需的真实历史日K不足20根时，系统会拒绝记录并提示先补齐行情，不会用模拟数据或不完整数据代替。

## 数据与风险说明

- 数据库默认保存在 `data/lianghua.db`，已加入忽略列表。
- 沪深价格以 CNY、港股价格以 HKD 分别核算，不做跨币种组合汇总。
- 盘中日 K 和周 K 信号可能随最新价格变化；界面会标记为“盘中暂定”。
- 模拟成交不包含真实券商的佣金、印花税、滑点、停牌、涨跌停排队和网络异常，不可作为实盘成交保证。
- 本工具仅用于个人研究与模拟，不构成投资建议。免费公开行情可能延迟、中断或调整接口。
